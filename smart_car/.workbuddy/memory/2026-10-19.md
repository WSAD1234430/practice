> 项目背景全部在 `2026-10-14.md`（App v1 已交付、装在一加 Ace 3 上、APK 备份在 `E:\practice\word_app\单词点读App.apk`）。
> 今天用户提出「单词本」+「跨页点读」的新需求，**明确要求先评审、不动代码**。

## 用户原话需求（6 条，务必保留原文语义）
1. 记录所有拍过的单词（**合法**且**不重复**；合法的定义 = 满足条件后能出现在点读区域的单词）并写进一个 txt 文件
2. txt 中**一个单词一行**，文件**保存在手机上**
3. 记录的单词在软件中也能看见，**入口放左上角，叫「单词本」**
4. 拍的单词**一页一页**的，所以单词本**也是一页一页的**（以拍的照片为准）
5. 左上角单词本**可以进入点读**
6. **点读要能跨页**：从第 1 页能一路「下一个」到第 2、3… 页；拍了新的一页，能「上一个」回到上一页

## 我发现的硬冲突（最重要）
**要求 1「不重复」 与 要求 6「跨页连续点读」互斥。**
- 若**全局去重**（一个词只在 txt 里出现一次）：第 2 页里与第 1 页重复的词会被剔除 → 跨页点到第 2 页时缺词，第 2 页变残。
- 若**不去重**：txt 里同词出现多次，违背「不重复」。

**建议解法（三层分别定义去重范围）**：
- 点读（App 内）：**每页完整保留**，跨页才能连续
- txt 文件：**全局唯一**，写在它第一次出现的位置（= 用户说的「不重复」字面义，且适合导入外部背单词软件）
- 单词本界面：**按页显示完整内容**，重复词标注「第 N 页也有」
- 备选（若用户想要 txt 严格按页、允许重复）：反过来做，需用户拍板

## 我拟定的默认值（等用户回「按默认」）
1. **入库时机**：点「开始点读」那一刻（词表已确认）。拍完直接回首页 → 不算。
2. **点读页改词/删词 → txt 同步**（否则 OCR 错字永远留在 txt）。实现上**每次改动重写整个 txt**，不做追加（避免去重/改词不一致）。
3. **同一页拍两次**：算两页，不自动判断（词重合度判断易误判），靠手动删页。
4. **txt 位置**：`内部存储/Download/单词点读/单词表.txt`（用 MediaStore，免危险权限，文件管理器可见、可拷到电脑）。
5. **页标识**：单词本里显示「第 3 页 · 10月19日 17:05 · 58 个词」。
6. **跨页进度显示**：`第 2 页 · 3/58`（不是全局 61/340）。
7. **跨页时「列表」弹层**：显示当前页，顶部可翻上一页/下一页。
8. **首页「继续点读」**：语义改为「跳到最后一页上次的位置」。

## 用户漏掉、但一定会遇到的问题
1. **删页**（必须有）：拍错页 / 拍重复页 / 测试页会一直堆，没有删除单词本很快变垃圾。
2. **清空全部**。
3. **txt 是"活文件"还是"快照"**：建议活文件——App 里任何改动都自动重写 txt。

## 技术风险
1. **存储权限**：App 私有目录普通文件管理器看不到（用户说"保存在手机上"很可能是想自己能找到/拷走）→ 需走 MediaStore 写 Download。
2. **跨页点读是 v1 之后最大的一次重构**：现在点读页只认「一页的 `List<WordItem>`」，要改成「多页 + 当前页索引」。会牵动 `ReadPage` / `WordSession`（进度存档，现在只存一页）/ 列表弹层 / 修改删除逻辑 / 首页「继续点读」。
3. **与早前设计文档冲突**：原设计明确「不做生词本/历史记录、用完即弃」，现在改为永久积累 → 存储与 txt 维护策略都要重定。早前「首页不放任何文字」的要求也要放宽（左上角要加「单词本」按钮）。

## 已实现（全部完成，BUILD SUCCESSFUL + 已装机 + 无 FATAL）
### 新文件 `WordNotebook.kt`
- `NotebookPage(id=拍摄时间戳, createdAt, dual, words: List<WordItem>, added: List<String>)`；`orderedTexts()` = `sortWords(words,dual)` + added（顺序 = 点读顺序）
- 内部存档：`files/notebook.json`（**先写 .tmp 再 rename**，防写一半把单词本写坏）
- `findDuplicate()`：**重合率 = 交集 / min(两页词数)**（这样"一次认58个、一次55个"也能抓到），阈值 **0.7**
- `exportTxt()`：按页序+页内序，**全局去重**，纯词表一行一个词
  - 写到 `Download/单词点读/单词表.txt`，走 **MediaStore**（API 29+，无需危险权限）；**先删同名旧文件再插入**，否则会变成「单词表(1).txt」；写入用 IS_PENDING 包裹
  - API < 29 兜底写 `getExternalFilesDir`

### 跨页点读的实现思路（重要，省了大量重构）
**没有**把 ReadPage 改成"多页模型"，而是**切换"当前工作页"**：
- `openPage(p, startAt)` 把目标页的 words/added/dual 装回 `rawWords`/`addedWords`/`dual`，设置 `currentPageId`、`readIndex`
- ReadPage 数据模型不变，只新增 `pageNo` / `hasPrevPage` / `hasNextPage` / `onPrevPage` / `onNextPage`
- 按钮逻辑：到本页边界才跨页（下一个 = 本页读完 → 下一页第 1 个；上一个 = 本页第 1 个 → 上一页最后一个）
- 进度显示：`第N页 · i/size`

### 关键状态 `currentPageId`
- `null` = 草稿（还没入库）；非 `null` = 已入库
- 已入库时，词一改就同步回 notebook 并重写 txt（**内容相同则跳过**，避免跨页导航时无谓写盘）
- ★ **踩点（差点写成 bug）**：**新拍一页必须把 `currentPageId` 置 null**，否则新页的词会把单词本里上一页覆盖掉 → 已在 `LaunchedEffect(photoUri)` 和「首页」按钮两处处理
- `WordSession` 增加 `pageId`；恢复时**校验该页是否还在**（被删则退回草稿）

### UI
- TopAppBar 的 `title` 位置放「单词本」按钮（左上角）；标题文字仍保持为空

### 缺词报告（undergraduate / performance）→ 落盘诊断一次命中两个 bug
用户用豆包对差集反馈："少了 undergraduate、performance，多了无"。**`files/last_ocr.txt` 直接把原因摊开了**：
```
第 51 行: [nperformance [pə' fo:məns] n. À; ofil]
第 56 行: [endure [n'djuə(r)] ; ; B; Bö undergraduate [Andə'grædzuət] n. tKAE]
被丢掉的词: ibe cin sbom ompo xion nperformance
```
- **Bug 1（结构缺陷）**：OCR 把两行挤成一行 → 我原来"从第一个 `[` 处截断"的规则把第二个词头 `undergraduate` 一起砍了。
  - **修复：换判据 —— 「紧跟左括号的那个 token 才是词头」**（`HEADWORD_BEFORE_BRACKET = ([A-Za-z][A-Za-z'\-]*)\s*[\[【(（]`）。一行里出现几次就有几个词头；左括号丢了才退回老办法。
  - 副产品：还顺手解决了"括号后面多认出一个词"的问题（原先把 `Unit 17` 的 `unit` 当词捞出来）。
- **Bug 2**：OCR 把词性标记 `n` 粘到词头 → `nperformance` → 不在词典 → 被丢。
  - **修复：`stripPosPrefix()`** —— 只在词不在词典时才试；切掉 `adj/adv/prep/conj/pron/num/vt/vi/ad/n/a/v`（长的优先），剩下那截必须**本身就是真词且长度 ≥3** 才采用。
- 与 `fixOcrConfusion()` 串成一条链：先猜认错字母 → 再猜词性粘连 → 都不行才丢弃（并记进"被丢掉的词"）。
- **离线用真实 OCR 原文验证**：8 行样本，新规则全对；`undergraduate`、`performance` 均恢复；`pension`/`fertile`/`excess`/`expose` 等不误伤、垃圾零新增。
- 已 BUILD SUCCESSFUL + 覆盖安装、启动无 FATAL。
- 经验：**落盘诊断这次一次就定位了两个 bug**，比之前抢 logcat 高效得多。以后遇到"少了某词"，第一步永远是 `adb shell run-as com.example.wordreader cat files/last_ocr.txt`。

### 又一轮缺词（increasingly / reflection，多 bein）→ 修 2 个，1 个修不了
诊断文件证据（`files/last_ocr.txt`）：
- **`reflection` 少的 → 我的正则漏洞**：OCR 把并列写法粘成 `reflection/-xion [rr'flekfn] …`；原正则 `[A-Za-z'\-]` 不含 `/`，只能抓到尾巴 `xion`（不在词典）→ 整个词头丢。
  - **修复**：`HEADWORD_BEFORE_BRACKET` 字符集加入 `/`，再对匹配结果**按 `/` 拆开分别判断**，哪段是真词留哪段。

  - **修复**：新增 `LEADING_WORD_THEN_CLOSE_PAREN = ^[A-Za-z][A-Za-z'\-]*[)）]`，命中则**整行丢掉**（只在没有"词+括号"词头、走 fallback 分支时判断）。真词头后面不会紧跟右括号。
- **`increasingly` 少的 → 改代码救不了**：该词**在 OCR 原文里完全不存在**。看坐标能确认是整行没读到：
  ```
  decrease y=579 → (空档 311px) → agriculture y=890    正常行距只有 ~78px
  ```
  即那块有约 3 行根本没被 OCR 认出来（反光/弯曲/阴影）→ 只能重拍。
- 离线用真实原文验证 **9 项全过**（reflection/-xion → reflection；bein) sbom] → 空；其余 7 个回归项不误伤）。

### 又一轮（多出 mot）→ 兜底路径收紧

### ★ 重要判断：规则式过滤已接近极限
连续 4 轮缺词/多词排查后，剩下的错误只剩两类，**都不是规则能治的**：
1. **OCR 把中文认成字母，且恰好凑成一个生僻真词**（`titi` / `bein` / `mot`）→ 只能靠**黑名单**；
2. **OCR 整行没读到**（如 `increasingly` 那页，y 从 579 直接跳到 890）→ 只能**重拍**（照片反光/弯曲）。
→ 后续不要再无脑堆正则（会开始误伤真词）；优先做"漏行提示"和引导他用黑名单。
