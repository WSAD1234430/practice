# 单词拍照点读 App —— 完整记录（设计文档 + 讨论纪要）

> 用途：个人自用安卓小工具，通过拍照识别单词本上的打印单词，按顺序逐词点读，播放标准英音真人发音。
> 本文档 = ① 设计文档（v1.0） + ② 设计过程中的讨论决定与答疑记录。
> 所有 ⚠️ 标记处为暂定方案，实施时可按实际情况调整。

# 第一部分：设计文档

## 一、产品定位

| 项目 | 说明 |
|---|---|
| **目标用户** | 本人（备考四六级，需要一个能快速「拍照 → 听发音」的工具） |
| **核心价值** | 拍一页单词本，就能按顺序一个一个听到标准英音，替代手动查词典 |
| **产品形态** | 安卓 App，单机、自用、无账号、无云端存储 |
| **不做什么** | ❌ 不做生词本 / 历史记录（一次一拍，用完即弃）<br>❌ 不做社交、分享<br>❌ 不做复杂自动分栏（v1 手动兜底） |

---

## 二、核心流程

```
拍照 / 从相册选图
      ↓
[确认页] 看识别结果，错了手动改
      ↓
自动切分单词（丢弃词性、序号、标点）
      ↓
按「列优先」排序（从上到下，左列念完再念右列）
      ↓
[点读页] 大字显示第 1 个词 + 自动发声
      ↓
点一下 → 下一个词出现 + 自动发声 → …… 直到念完
```

## 三、功能清单

### 3.1 拍照 / 选图

| 功能 | 决定 | 备注 |
|---|---|---|
| 打开相机拍摄 | ✅ | |
| 从相册选图 | ✅ | 不只是实时拍 |
| 裁剪框 | ✅ | 只识别框选区域，避开页眉页脚、排除干扰；**建议裁剪框直接叠在拍照页上，不单独做裁剪页** |
| 拍完确认 | ✅ | 先看效果，不满意可重拍 |
| 拍歪处理 | ✅ | 提示重拍（不做自动矫正） |

### 3.2 识别与纠错

| 功能 | 决定 | 备注 |
|---|---|---|
| OCR 引擎 | **离线 ML Kit**（印刷体够用） | 免费、离线、无需 Key；一页单词约 0.1~1 秒 |
| 识别结果展示 | ✅ 列表显示所有词 | 用户对书扫一眼即可发现错误 |
| 人工纠错 | ✅ 点单词可修改 | 不做智能候选，手动输入即可 |
| 词库校验 | ❌ 不做 | 靠人眼纠错 |
| 自动报错标记 | ❌ 不做 | 同上 |

> ⚠️ `clear → dear` 这类「错成真词」的错误机器发现不了，只能靠对着书核对。建议识别结果列表**始终可见**。

### 3.3 单词切分

**处理逻辑（从简）：**

```
OCR 原始文字
   ↓ 按空格 / 换行拆开
   ↓ 去掉首尾标点（, . ; : " ' ! ? ( ) [ ]【】等）
   ↓ 只保留「纯字母」或「字母 + 撇号 / 连字符」
   ↓ 丢弃：词性 (n.)(v.)、序号 1.①②、音标 /ˈæpl/、中文
   ↓ 得到最终单词列表
```

| 情况 | 处理 |
|---|---|
| `apple,` `dog.` | 去掉标点 → `apple` `dog` |
| `don't` `it's` | 保留（撇号属单词一部分） |
| `well-known` | 保留整词（词典可查） |
| `ice cream` | 拆为 `ice` + `cream`，各念各的 |
| `(n.)` `1.` `[ ]` | 丢弃 |
| 中文词义 | 丢弃 |

### 3.4 排序（⚠️ v1 用简单方案）

| 项目 | 决定 |
|---|---|
| 目标顺序 | 从上到下；**双栏时，左列念完再念右列** |
| v1 方案 | ⚠️ **先按 y 坐标排序（从上到下），提供「行优先 / 列优先」手动切换按钮** |
| 自动分栏 | 🅿️ **暂不实现**（算法复杂，易误判，后置版本再做） |
| 兜底 | 识别后让用户确认顺序，错了手动切模式 |

> **已知难点（本项目唯一技术难点）：**
> 双栏版式中，「列」的自动判断需要按 x 坐标聚类。遇到「左边长词 / 右边短词」时坐标会交错（如 `beautiful` 的右边界可能比 `cat` 的左边界更靠右），自动判断易失败。
> 举例：版式为 `apple/banana`、`cat/dog`、`egg/fish`（每行两列），
> - 想要顺序：`apple → cat → egg → banana → dog → fish`（列优先）
> - 易错顺序：`apple → banana → cat → dog → egg → fish`（行优先，❌）
> 故 v1 用「手动切换」兜底。

### 3.5 音频（发音）

| 项目 | 决定 |
|---|---|
| 音源类型 | **词典真人音**（非机械 TTS） |
| 具体来源 | 有道词典音频直链一类（`type` 参数区分口音） |
| 口音 | **英音**（四六级以英式发音为主） |
| 兜底方案 | ⚠️ 词无音源时：**跳过**（v1 简单处理） |
| 缓存 | ✅ **本地缓存**，同一词只下一次，永久留存 |
| 多音词 / 变形词 | ⏸ 暂不处理（`read` / `lead` 等可能读音不准，v1 接受） |

### 3.6 点读播放

| 项目 | 决定 |
|---|---|
| 显示方式 | ⚠️ **大字居中显示当前词**（单词卡形式） |
| 切换方式 | ⚠️ **点击屏幕任意处**（或「下一个」按钮，二选一） |
| 自动发声 | ✅ 每次切到新词，自动念一次 |
| 手动重听 | ✅ 点当前词，重念一次 |
| 连续播放 | ❌ 不会自己一直念，必须手动点 |
| 显示音标 | ⚠️ 待定（备考建议显示，v1 可先不做） |
| 「上一个」 | ⚠️ 待定（建议保留，便于念错回退） |
| 念完表现 | ⚠️ 停在最后一个词 / 提示「已念完」 |

### 3.7 数据保存

| 项目 | 决定 |
|---|---|
| 历史记录 | ❌ 不要 |
| 生词本 | ❌ 不要 |
| 使用模式 | 一次一拍，用完即弃 |

# 第二部分：设计过程讨论纪要（常见问题答疑）

## 1. 有没有现成软件？

**没有完整现成的。** 有「拍照识字」、有「文字朗读」，但把「拍照→自动排序→逐词发音」串成一条完整流水线并逐词发音的，需要自己拼或自己做。

- 临时用：拍完发 AI 让它按顺序提取，再丢进朗读工具；
- 长期用：自己做 App。

## 2. 安卓上怎么实现？

- **OCR**：ML Kit Text Recognition v2（官方、离线、免费、返回带坐标的文本树）
- **排序**：按坐标排（先按 y 从上到下；双栏时按 x 分列）
- **发音**：词典真人音（有道等），本地缓存

## 3. 要不要做原型 / UI 设计？

- **原型（肯定要）**：帮自己想清楚结构。工具推荐：**即时设计**（中文免费）或 **Figma**（免费版够用）。
- **UI 高保真**：自用 App 可后置，用系统默认组件就好看。
- **⚠️ 注意**：墨刀付费门槛较高，免费替代首选 **即时设计 (js.design)**、**Figma**；画草稿用纸笔也行。

## 4. 画布尺寸怎么选？（一加 Ace 3）

| 参数 | 值 |
|---|---|
| 物理分辨率 | 2780 × 1264 px |
| **逻辑尺寸（画布选这个）** | **≈ 412 × 915 dp** |

- 选不到一加型号，**选 `Pixel` 系列**（宽度同为 412dp）或 **`Android 412×915`** 即可；
- 差 50dp 不影响，安卓界面自适应。

## 5. 墨刀操作要点

| 需求 | 做法 |
|---|---|
| 按钮跳转第二页 | 选中按钮 → 右侧「交互」→ 单击 → 跳转页面 → 选目标页面 |
| 改按钮文字 | **双击**文字直接改，或属性栏改「文本」 |
| 拍照页 | **要画**（黑底 + 裁剪框 + 圆形快门 + 相册图标），但**不用实现真拍照** |
| 图标（对勾✓ / 重拍↻） | 优先用**墨刀自带图标库**（搜 check / refresh），或 **iconfont.cn** 免费下载，或直接打字符 ✓ ↻ |
| 交互三要素 | **触发**（单击/长按）→ **动作**（跳转/显示隐藏/移动/切换状态）→ **动画**（淡入/滑入/放大） |
| 点击原地放大 | 复制一份放大版 → 设为初始隐藏 → 点击时「切换可见性/状态」 |
| 点击侧边滑出半屏 | 面板初始置于屏幕外 → 点击时「移动」到屏幕内 + 选滑入动画（200~300ms） |

## 6. 墨刀只能做原型吗？能做实际的样子吗？

- **视觉上**：能做得非常像成品（高保真设计稿）；
- **功能上**：❌ 不能真跑（拍照、OCR、发音都做不到）。
- 比喻：**墨刀 = 房子效果图；Android Studio = 施工队。**

## 7. 原型的占位符

- 占位符 = 先占位置的假内容，目的是**定布局、定大小**，真内容后面再填；
- 你的单词列表、大字、音标位置，都用**示例单词（apple/banana）** 当占位符；
- 线框图用**灰块占位**；高保真稿用**假数据**填满。

## 8. 每个功能都要在墨刀实现吗？

**不用。** 原则：**只画用户看得见的界面。**

| 功能 | 画不画 |
|---|---|
| 拍照 / 确认 / 点读 | ✅ 画 |
| 裁剪 | 看设计（叠在拍照页 → 不用单独画） |
| OCR / 下载音频 / 排序 / 缓存 | ❌ 不画，写「备注」说明即可 |

## 9. OCR 快吗？要加等待界面吗？

| 方案 | 耗时 |
|---|---|
| 离线 ML Kit | **0.1 ~ 1 秒**（很快） |
| 云端 OCR | 0.5 ~ 3 秒 |

- **离线基本不用加等待**；云端建议加转圈；
- **不加等待会不会出 bug？→ 不会崩溃**，只是可能「画面先空一下，内容后出现」；
- **自用建议：先不加，用出问题再加一句「识别中...」文字**，不必做完整等待页；
- **真正慢的是音频下载**，不是 OCR。

**体验原则：识别后立即显示单词列表（不阻塞）；音频后台异步下载，进入点读页前预加载前几个词。**

## 10. 切后台会不会自动关？

- **不会自动关**，只是暂停（Background）；切回来通常还在；
- **可能丢**：内存紧张或被系统杀后台时（国产 ROM 杀后台较狠），需重新拍摄；
- **声音不会一直响**（你的设计本就是点一次念一次）；
- **v1 可不处理**，真遇到频繁丢再加「临时状态恢复」。

## 11. 四六级是英音还是美音？

**以英式发音为主**（个别录音会混美音）。建议：
- 音源默认**英音**；
- 可加英音/美音开关（几乎不增加开发量）；
- 音标与音频保持一致（看着英标、听着美音会误导）。

## 12. 音频为什么不能只用"好听"的？

- 「好听」与「离线/免费」基本不能兼得；
- 你要的是**单词级真人音**（词典音），这是最不缺资源的一环；
- 真正的依赖是 **OCR 准确性 + 文字清洗**：OCR 错一个字母，该词就查不到音；
- 必须做**本地缓存**（防接口失效、省流量、无网可用）。

## 13. 单词本双栏、顺序问题

- OCR 默认顺序常是「从左到右、逐行」，对你的双栏版式会**先左右再上下**（❌）；
- 必须自己做排序，**按坐标**：先按 y 从上到下，双栏时按 x 分列，左列念完再念右列；
- **自动分列有误判风险**，v1 用手动「行/列优先」切换兜底。
